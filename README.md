# Внеурок

**От идеи до школьного события.**

Бот помогает предложить дело, найти помощников, согласовать помещение с педагогом, открыть запись и сохранить результат. Например, школьники могут вместе провести мастерскую по созданию игр или встречу своей команды.

Бот проекта: **https://max.ru/ideya_fiks_111_bot**.

Код бота и учебный пример готовы для проверки. Подключение этого кода к MAX ещё не выполнено: нужен токен и сервер. Наличие ссылки само по себе не означает, что бот уже отвечает.

## Что можно сделать

- Создать идею и добавить задачи для помощников.
- Отправить её педагогу. Педагог может согласовать или вернуть замечания.
- Выбрать помещение и время без двойного бронирования.
- Открыть запись с ограничением числа мест.
- Отменить запись или само событие.
- После встречи отметить присутствовавших и подвести итог.

При изменении условий прежнее согласование и записи отменяются. Ученик не может согласовать собственную заявку или назначить себе роль педагога.

## Учебный пример в боте

После подключения начните с `/start`, затем `/demo`. Этот пример видите только вы; настоящих школьных данных в нём нет.

В примере можно переключаться между автором, помощником, участником и педагогом. Команда `/help` показывает действия. `/demo_end ID` позволяет показать завершение учебного события без ожидания. Это не считается настоящим проведённым мероприятием.

Для настоящей школы предусмотрен отдельный вход `/school`. Его можно использовать только после приглашения и назначения роли школой.

## Запуск из командной строки

Нужен **Python 3.12 или новее**. Используется только стандартная библиотека Python. Сторонних библиотек нет, это отмечено в `requirements.txt`.

Локальный интерфейс для проверки:

```sh
git clone https://github.com/raastaa/vneurok-max.git
cd vneurok-max
python3 -m vneurok.server
```

Откройте http://127.0.0.1:8765 на этом же компьютере. Данные вымышленные, выбор роли относится только к демонстрации. Остановка: `Ctrl+C`.

Бот с реальным подключением MAX:

```sh
python3 scripts/configure.py
python3 -m vneurok.server --max-mode --send-enabled --env-file .env --db data/pilot.db
```

Первую команду выполняет владелец бота. Она спрашивает HTTPS-адрес и скрыто принимает токен, сохраняет настройки только в локальный `.env`. Вторая команда запускает реальные ответы в MAX, поэтому её следует использовать только после настройки и разрешения владельца. Сам токен в README, чат или GitHub копировать не нужно.

## Сборка и запуск контейнера

```sh
docker build -t vneurok-max:local .
docker compose --env-file .env up --build -d
```

Контейнер использует `python:3.12-slim`. Настройки находятся в `.env`, данные сохраняются в отдельном томе. Порт 8765 открыт только на этом компьютере. Перед ним нужен HTTPS-сервер; его адрес должен совпадать с `APP_ORIGIN`.

Сохранить готовый Docker-образ:

```sh
docker save vneurok-max:local | gzip > vneurok-max-docker.tar.gz
```

Загрузить сохранённый образ:

```sh
gunzip -c vneurok-max-docker.tar.gz | docker load
```

Готовый образ **Linux amd64, версия v0.1.0**: [скачать из Releases](https://github.com/raastaa/vneurok-max/releases/tag/v0.1.0). Рядом находятся `SHA256SUMS` и сведения об образе. Это образ коммита `04cae8b6bc5e986dc44e4063e61c89cfbc9913ca`, а не автоматически самая новая версия ветки.

Проверка архива перед загрузкой:

```sh
sha256sum -c SHA256SUMS
# На macOS: shasum -a 256 -c SHA256SUMS
```

[Проверка и сборка этого образа](https://github.com/raastaa/vneurok-max/actions/runs/42335063621) завершились успешно. Новые сборки также сохраняются в **Actions → Проверка проекта → Artifacts → vneurok-max-docker** на 30 дней; для подачи используйте постоянную ссылку на Releases.

## Подключение MAX

1. У владельца есть зарегистрированный бот `ideya_fiks_111_bot` и его токен.
2. Приложение работает на выбранном сервере с HTTPS.
3. В MAX настроены события `bot_started` и `message_created` на адрес `https://ваш-домен/api/max/webhook`.
4. Секрет webhook совпадает с локальным `MAX_WEBHOOK_SECRET`.
5. Проверены `/start`, учебный маршрут и получение ответов с настоящего аккаунта MAX.

До подключения можно выполнить безопасную местную проверку:

```sh
python3 -m vneurok.readiness --env-file .env
```

Она не создаёт файлы, не выводит значения секретов, не обращается к MAX и не меняет настройки. Успех означает только корректность местной конфигурации, не работающего бота. Подробный порядок запуска и приёмки: [docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md).

Эти действия не выполняются автоматически при скачивании проекта. Школьные данные нельзя загружать в учебный пример. Перед настоящим использованием школа определяет участников, права и правила хранения данных.

## Проверка проекта

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q vneurok tests scripts
node --check web/app.js
```

Тесты проверяют обычный путь, права, повторные действия, одновременную бронь, последнее свободное место и обработку сбоев. Node нужен только для отдельной проверки файла интерфейса, не для запуска бота.

## Что ещё не готово

Это первый рабочий вариант, а не завершённый школьный пилот. Пока нет удобной панели приглашений, редактирования расписания помещений и подписок по интересам. Реальный запуск в MAX и проверка контейнера отмечаются отдельно, без подмены их локальной демонстрацией.

Заявку на конкурс отправляет капитан команды.
