# Внеурок

**От идеи до школьного события.**

Бот помогает предложить дело, найти помощников, согласовать помещение с педагогом, открыть запись и сохранить результат. Например, школьники могут вместе провести мастерскую по созданию игр или встречу своей команды.

Бот проекта: **https://max.ru/ideya_fiks_111_bot**.

Код и Docker-образ проверены. Живой бот пока не подключён; его запуск отложен по решению владельца. Ссылка выше ведёт на зарегистрированного бота, но его ответы ещё не проверены.

Для капитана: [что готово, где взять проверенный образ и что осталось перед подачей](docs/SUBMISSION_CHECKLIST.md).

## Что можно сделать

- Сохранить короткий черновик, затем выбрать аудиторию: свой класс, параллель или школу.
- Пригласить помощников из разрешённого школьного списка и распределить задачи до согласования.
- Выбрать тему интереса, подписаться на её события или на изменения одной карточки.
- Запросить помещение с оборудованием, правилами, вместимостью и ответственным либо выбрать сценарий без помещения.
- Получить решение педагога: согласовать, вернуть с замечанием, отложить или отказать.
- После согласования открыть запись, не превышая число мест; отменить запись или событие.
- После встречи сохранить итог и получить отдельное подтверждение педагога с явной посещаемостью.
- Администратору: подключить школу, классы, пользователей и взрослых, пространства и разрешённые интервалы; выдать именное приглашение и разобрать сбой доставки.

Закрытая встреча видна только своей команде и куратору. Данные школ разделены. Несогласованная редакция не публикуется. После изменения условий прежнее согласование и записи снимаются; участник получает безопасное уведомление и при новом открытии записывается заново. Старые сообщения не должны оживать после изменения условий или отзыва доступа.

Полная сверка: [матрица исходной заявки](docs/REQUIREMENTS_MATRIX.md). Сценарии, ожидаемые результаты и границы проверки: [тестовые кейсы](docs/TEST_SCENARIOS.md).

## Учебный пример в боте

После подключения начните с `/start`, затем `/demo`. Этот пример видите только вы; настоящих школьных данных в нём нет.

В примере можно переключаться между автором, помощником, участником и педагогом. Команда `/help` показывает действия. `/new` и `/plan` ведут по шагам, варианты выбираются номером; доступны `/back`, `/cancel`, `/resume`. Кнопки меню отправляют обычные команды MAX. `/demo_end ID` позволяет показать завершение учебного события без ожидания. Это не считается настоящим проведённым мероприятием.

Проверяемая последовательность: `/invite ID student-helper` → помощник берёт задачу → автор `/submit ID` → педагог `/approve ID` → автор `/open ID` → участник `/join ID`. После учебного `/demo_end ID`: педагог `/attend ID student-visitor да` (или `нет`), автор `/result ID текст итога`, педагог `/confirm ID`. Подписка: `/follow ID`, отписка: `/unfollow ID` (сообщения по активной записи и роли в команде сохраняются); школьный код для приглашения: `/me`.

Для настоящей школы предусмотрен отдельный вход `/school CODE` по именному приглашению, привязанному к своему MAX ID. `/identity` показывает этот ID без назначения роли. Первого взрослого администратора создаёт уполномоченный оператор: [настройка школы](docs/SCHOOL_SETUP.md). Реальные данные не вносят в `/demo`.

## Запуск из командной строки

Нужен **Python 3.12 или новее**. Используется только стандартная библиотека Python. Сторонних библиотек нет, это отмечено в `requirements.txt`.

Локальный интерфейс для проверки:

```sh
git clone https://github.com/raastaa/vneurok-max.git
cd vneurok-max
python3 -m vneurok.server
```

Откройте http://127.0.0.1:8765 на этом же компьютере. Данные вымышленные, выбор роли относится только к демонстрации. Остановка: `Ctrl+C`.

Бот с реальным подключением MAX:

```sh
python3 scripts/configure.py
python3 -m vneurok.server --max-mode --send-enabled --env-file .env --db data/pilot.db
```

Первую команду выполняет владелец бота. Она спрашивает HTTPS-адрес и скрыто принимает токен, сохраняет настройки только в локальный `.env`. Вторая команда запускает реальные ответы в MAX, поэтому её следует использовать только после настройки и разрешения владельца. Сам токен в README, чат или GitHub копировать не нужно.

## Сборка и запуск контейнера

```sh
docker build -t vneurok-max:local .
docker compose --env-file .env up --build -d
```

Контейнер использует `python:3.12-slim`. Настройки находятся в `.env`, данные сохраняются в отдельном томе. Порт 8765 открыт только на этом компьютере. Перед ним нужен HTTPS-сервер; его адрес должен совпадать с `APP_ORIGIN`.

Сохранить готовый Docker-образ:

```sh
docker save vneurok-max:local | gzip > vneurok-max-docker.tar.gz
```

Загрузить сохранённый образ:

```sh
gunzip -c vneurok-max-docker.tar.gz | docker load
```

## Подключение MAX

1. У владельца есть зарегистрированный бот `ideya_fiks_111_bot` и его токен.
2. Приложение работает на выбранном сервере с HTTPS.
3. В MAX настроены события `bot_started` и `message_created` на адрес `https://ваш-домен/api/max/webhook`.
4. Секрет webhook совпадает с локальным `MAX_WEBHOOK_SECRET`.
5. Проверены `/start`, учебный маршрут и получение ответов с настоящего аккаунта MAX.

До подключения можно выполнить безопасную местную проверку:

```sh
python3 -m vneurok.readiness --env-file .env
```

Она не создаёт файлы, не выводит значения секретов, не обращается к MAX и не меняет настройки. Успех означает только корректность местной конфигурации, не работающего бота. Подробный порядок запуска и приёмки: [docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md).

Эти действия не выполняются автоматически при скачивании проекта. Школьные данные нельзя загружать в учебный пример. Перед настоящим использованием школа определяет участников, права и правила хранения данных.

## Проверка проекта

```sh
python3 scripts/run_tests.py
# Сохранить подробный локальный журнал всех проверок:
python3 scripts/verify.py --output docs/TEST_RESULTS.json
python3 -m compileall -q vneurok tests scripts
node --check web/app.js
node tests/test_web_guided.js
```

Тесты проверяют обычный путь, права, повторные действия, одновременную бронь, последнее свободное место и обработку сбоев. Node нужен только для отдельной проверки файла интерфейса, не для запуска бота.

## Что ещё требует проверки

Docker-сборка исправленного коммита и её перезапуск проверены. Подключение MAX и реальные сообщения пока не проверены: нужны разрешённая настройка HTTPS, токена и webhook, затем приёмка на двух взрослых тестовых аккаунтах. До нового разрешения владельца эти действия не выполняются. Также нужен постоянный доступ к новому образу для подачи; опубликованный v0.1.0 устарел.

Школа отдельно утверждает участников, взрослые роли и [правила хранения/удаления](docs/DATA_POLICY.md). Автоматического удаления истории нет. Интервью, школьный пилот и целевые 3/1 минуты не считаются выполненными по результатам автоматических тестов.

HTTP 429 и доказанный сбой до соединения повторяются с задержкой и лимитом. Тайм-аут или неопределённый исход требует сверки в MAX; панель администратора разрешает повтор только после явного подтверждения недоставки. Слепой повтор мог бы создать дубли.

Исторический первый аудит: [docs/AUDIT_2026-11-08.md](docs/AUDIT_2026-11-08.md). Актуальный полный перечень: [docs/REQUIREMENTS_MATRIX.md](docs/REQUIREMENTS_MATRIX.md).
